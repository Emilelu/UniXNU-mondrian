## Research decision before implementation

The Lead-owned run e reaches the enabled publisher but refuses uninstalled owner acquire: [console:127](E:/k60-work/evidence/usblog-20261115-223916/console.log#L127). Stage 1 returns -1000, no lease is published and the battery consumer stays blocked. The late startup exclusion proves an attempt, not authentication.

The existing [one-shot SMC transport](../../../drivers/PongPower/K60AdspPas.c#L17) lacks a shared transaction lock, interrupted-session resume, busy retries and owned coherent metadata. [Rail discovery](../../../drivers/PongPower/K60PmicRail.c) does not acquire a complete ADSP power/XO/interconnect lease. Neither the startup CAS nor successful SHUTDOWN independently proves stopped state. The adapter therefore does not call those primitives as a successful ownership backend.

The sibling pong-power repository at E:/k60-work/references/pong-power, HEAD c117a6700968c944528570326c8d709e29bd373f, was fetched from https://github.com/Chengdong-Yu/pong-power.git before implementation. Its BSD-2-Clause-Patent licence matches this tree. PongAdsp.cpp:235–259 provides SCM resume/busy patterns, :261–268 cache maintenance, :301–322 prepared contiguous metadata and :342–367 bounded mappings. PongPlatformResources.cpp:184–191 supplies its shared lock. These patterns fit SM8475/Darwin; they do not establish K60 resource or stopped proofs.

Linux [android14 qcom_scm.c:464–518](https://android.googlesource.com/kernel/common/+/refs/heads/android14-6.1/drivers/firmware/qcom_scm.c?format=TEXT) requires contiguous aligned noncacheable PAS metadata and permits its release after a terminal INIT error. [android16 qcom_scm-smc.c:93–148](https://android.googlesource.com/kernel/common/+/refs/heads/android16-6.12/drivers/firmware/qcom/qcom_scm-smc.c?format=TEXT) treats WAITQ_SLEEP=2 as suspended: completion requires the secure IRQ/wait-context owner. The native adapter quarantines that and unknown positive results instead of guessing a resume or ACK.

## Installation and production boundary

[Runtime:47](../../../drivers/PongPower/K60HandoffRuntime.cpp#L47) calls k60_adsp_platform_install() after configuration, RAM overlap, chosen and OSData preflight; [runtime:48](../../../drivers/PongPower/K60HandoffRuntime.cpp#L48) then acquires. No new patch hunk is required. The [archive recipe](../../../scripts/build-k60-physical-battery.py#L342) includes both platform C and native C++ sources; this task did not build the archive, kernel or image.

[Install:250](../../../drivers/PongPower/K60AdspPlatform.c#L250) registers the complete version-1/sizeof [ops table](../../../drivers/PongPower/K60AdspPlatform.c#L234) at :263. Return 1 means only this function's own successful earlier installation. Unrelated installation failure is not idempotence. The static platform, immutable carrier pins and metadata outlive the runtime stack. Absent or zero-length carrier alone can select the already-mapped legacy FAT fallback; malformed present K60A remains an error.

The [ownership interface](../../../drivers/PongPower/K60AdspPlatform.h#L18) requires aggregate PAS1/GLINK/reset exclusion, a nonzero epoch/token, retained rails/XO/interconnect/QMP, independent stopped/live proofs and an SCM lock shared by all competing secure callers. [Ownership registration](../../../drivers/PongPower/K60AdspPlatformNative.cpp#L368) has no production caller in this checkpoint. No GLINK worker is started or adopted by the producer. The missing board service keeps available=0; a startup CAS, discovered register, or fake callback cannot replace it.

The native code implements releasable page-containing IOKit maps, exact requested subranges, 256 KiB firmware windows, byte COPY/BSS, PoC synchronization, bounded TCSR acquisition and serialized SCM. [Metadata allocation](../../../drivers/PongPower/K60AdspPlatformNative.cpp#L307) is 64 KiB, physically contiguous, prepared, 4 KiB aligned, within 36-bit physical space and explicitly inhibited-cache. [SCM](../../../drivers/PongPower/K60AdspPlatformNative.cpp#L264) retains the shared lock through interrupted x6 resumes and up to 20 busy attempts with 30 ms pauses. Suspended/unknown-positive results or exhausted resumes poison the native state and retain lock, metadata and resources; no further SMC or stopped proof is permitted. Releasable IOMemoryDescriptor/IOMemoryMap mappings replace the suggested ml_io_map so safe abort can actually release both mappings; they still return exact configured bytes and checked alignment.

Safe abort follows PAS shutdown and independent stopped proof, unmap, image close, resource release, exclusive release. The final read-only stopped query checks the live reserved token, absence of retained SCM/TCSR state, terminal shutdown after any AUTH attempt and independent board stopped proof; it does not require acquired resources. The board exclusion keeps that proof stable through exclusive release, including after resources release, and forbids callback reentry. Valid void releases therefore do not query mutable stopped evidence again or introduce a new cleanup failure. A failure before AUTH does not require a fabricated shutdown. AUTH uncertainty or a suspended SCM session must retain ownership as Poisoned, so the request to clear all fields applies only to proven-safe rollback. Published ownership is retained indefinitely.

## Board ownership: what each of the ten callbacks proves

[K60AdspBoard.c](../../../drivers/PongPower/K60AdspBoard.c) fills the ten-entry [K60AdspPlatformOwnership](../../../drivers/PongPower/K60AdspPlatform.h#L28) table at [init:313](../../../drivers/PongPower/K60AdspBoard.c#L313). Every verdict is one of the board facts below or a named refusal; no callback reports success it cannot show. The whole file issues no SMC and never maps 0x17a00000, writes a TCS word or triggers an RPMh transaction, because [HARD-RULES.md:24-119](../ops/HARD-RULES.md#L24) forbids all three without exception.

The host test [test-k60-adsp-board.c](../../../scripts/tests/test-k60-adsp-board.c) links the board, the real SMEM parser and the real startup arbitration and **nothing else**. The PAS transport is deliberately absent from that link, so an SMC issued from the board would fail the build instead of the test: "the board issues no monitor call" is a link-time fact here. Physical access is counted through the injected [K60AdspBoardIo](../../../drivers/PongPower/K60AdspBoard.h#L41) table.

| Callback | Implementation | What it proves | What it does not prove |
| --- | --- | --- | --- |
| available | [C:195](../../../drivers/PongPower/K60AdspBoard.c#L195) | Arithmetic only: this service is initialized and unpoisoned, its io table is complete, and the config is the pinned board ([config_ok:64](../../../drivers/PongPower/K60AdspBoard.c#L64): SMEM 0x80900000/2 MiB, ADSP 0x9fd00000/0x3100000, mutex 0x1f4100c, IPCC 0xed18000, remote PID 2, client 3, signal 0, items 478/479/480/443, protocol 1). | Nothing physical. It never maps, reads SMEM or TCSR, or calls the monitor; the test asserts zero map/unmap calls for both verdicts and for every rejection (discovered address, wrong item, wrong protocol, null config). |
| exclusive | [C:201](../../../drivers/PongPower/K60AdspBoard.c#L201) | A real exclusion: [k60_adsp_handoff_owner_active()==1](../../../drivers/PongPower/K60AdspStartup.c#L10) means the early owner holds the startup CAS, so the late legacy loader can never claim owner 2 and can never reset or restart the DSP behind this lease. | exclusive_release | [C:231](../../../drivers/PongPower/K60AdspBoard.c#L231) | The lease and the window are gone: token, cookie, epoch, config, partition and mapping are cleared unconditionally, so the call cannot fail and cannot be conditional on a stale token. | Nothing else. | resources | [C:241](../../../drivers/PongPower/K60AdspBoard.c#L241) | That the lease, the exclusion and an independent stopped proof all still hold at this instant, then a deliberate refusal. | Retention itself. The callback therefore returns K60BoardUnsupported (-63) with that reason rather than reporting a vote it does not hold. |
| resources_release | [C:258](../../../drivers/PongPower/K60AdspBoard.c#L258) | That no resource flag survives, so a later live() cannot be confused with retention. | Nothing to undo: no vote was ever created, and the release is void and cannot fail. |

| live | [C:277](../../../drivers/PongPower/K60AdspBoard.c#L277) | The retained token alone: initialized, unpoisoned, this exact lease record by pointer, matching epoch, matching token contents, and the early owner still holding the CAS. | Anything about resource acquisition. | scm_lock | [C:293](../../../drivers/PongPower/K60AdspBoard.c#L293) | One kernel-global lock for **all** SCM clients: the compare-and-swap records the holder, so a second lock from the same board or a different board is K60BoardBusy (-64), never a recursive success. | The SMEM hardware mutex word at config.mutex_base; that stays the platform mapping layer's job ([K60AdspPlatform.c:136](../../../drivers/PongPower/K60AdspPlatform.c#L136)). |
| scm_unlock | [C:303](../../../drivers/PongPower/K60AdspBoard.c#L303) | That only the recorded holder releases the lock; a board that does not hold it is a no-op, which is the only safe behaviour a void release can have. | That the transaction completed. The caller's result handling stays in the native SCM path, which keeps the lock through interrupted resumes and poisons on suspended results. |

Two further properties are structural rather than per-callback. The lease ring has [two records](../../../drivers/PongPower/K60AdspBoard.h#L51), so consecutive grants return different cookies and a token from an earlier grant is rejected by pointer identity before the epoch is compared. And the stopped proof survives exclusive_release() in the sense that it is never cached: after release there is no lease, so stopped() and live() both return 0 rather than a stale 1, and a fresh lease re-proves the same state with a new epoch while the old cookie opens nothing.

The host test covers the five required scenarios and one negative suite: (1) available=0 touches no SMEM/TCSR and issues no SMC; (2) a failed exclusive rolls back epoch, token, cookie and window, including the mapped-but-foreign-SMEM case where the mapping must be released; (3) stopped stays provable and the SMEM image stays byte-identical across exclusive_release; (4) scm_lock is non-reentrant for one board and across two boards; (5) live proves the token while resources() is unavailable; plus announced, restart-pending, quiet, corrupt and absent SMP2P evidence. It prints `TESTS OK board-ownership: 6 scenarios`.

Installation is still the Lead's step: nothing in the tree calls [k60_adsp_board_init](../../../drivers/PongPower/K60AdspBoard.c#L313) or [k60_adsp_platform_ownership_install](../../../drivers/PongPower/K60AdspPlatformNative.cpp#L368) yet, so native availability stays 0 and [Native context:380](../../../drivers/PongPower/K60AdspPlatformNative.cpp#L380) still prints board_ownership=0. Wiring it means calling k60_adsp_board_init with [k60_adsp_board_kernel_io()](../../../drivers/PongPower/K60AdspBoard.c#L370) and installing [k60_adsp_board_ownership()](../../../drivers/PongPower/K60AdspBoard.c#L333) before the [platform install at runtime:47](../../../drivers/PongPower/K60HandoffRuntime.cpp#L47). Until that exists, the acceptance criterion is unchanged: published authenticated PAS1 epoch=N bytes=104 flags=15, with battery verify/local_verified/device still false.
