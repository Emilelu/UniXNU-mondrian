# 官方 GPU 路线在 K60（Adreno 730）上的落地计划

来源：<https://unixnu.com/zh/porting/gpu>（2026-11-17 精读）。目标不变：Metal 硬件加速 → 首帧 → 帧率 → 120 fps 跟手。

## 1. 官方链路与本机现状对照

| 官方环节 | 官方实现 | K60 现状 | 差距 |
|---|---|---|---|
| 交付 | payload `--gpu-addon` → `/chosen/memory-map/GpuAddon` → 内核写进 Data 卷 → `sheng-gpu-addon=1` 只读 union 到 `/System/Library/Extensions` | `0610` 内核内嵌 blob + 双 root 写入：真机 `K60METAL deploy files=6/6 inject=6 error=0`，`K60GPUADDON addons stage=5 status=0` | 已通（走的不是 `GpuAddon` 通道，但结果等价：bundle 在 `/private/var/ngpu/addons` 与 `/private/var/pong` 两处都在） |
| 插件 | `NativeAdrenoMetal.bundle`（`drivers/AdrenoMetal`），`MetalPluginName` → `NSBundle` → principal class → `IOServiceOpen(IOAcceleratorES)` | `PongAdrenoMetal.bundle`（`drivers/PongMetal`）：`Pong Metal: plugin loaded` → `real Vulkan-backed device created status=0x0` → `Turnip Adreno (TM) 725` | 已通（自研插件，不是官方插件） |
| 内核 KMD | `drivers/Adreno740`（SM8550 的 A740） | `drivers/PongAdreno`（A730，yibiya 线，曾出过 `present #`） | **代际不同**，见 §2 |
| 预热 | `--prime-list`（嵌 `__DATA,__primelist`）+ `--cache-export` → `make-m2vpack.py` → `--pipeline-pack` | 无 | 未做（性能项） |
| 渲染策略 | `TU_DEBUG=gmem,nocb`、`metal-flow=1`、`NATIVE_METAL_SINGLE_SAMPLE=0` | 无 | 未做（性能项） |

结论：交付层与预热层跟 GPU 代际无关，可以直接照搬；真正的代际工作是 KMD。

## 2. 官方 KMD 里有多少是 A740 专属（实测）

对 `drivers/Adreno740` 全树（92 个文件 / 11,589 行）按「是否出现 A740/SM8550/寄存器地址」分类：

- **代际专属：5 个文件 / 753 行**
  - `NativeAdrenoA740HwInit.h` 168 行 —— **生成文件**，不是手写
  - `NativeAdrenoGpuContext.h` 50、`NativeAdrenoPwrup.cpp` 58、`NativeAdrenoPwrup.h` 38、`NativeAdrenoPwrupRegs.h` 28
- **通用机器：87 个文件 / 10,836 行**（ring / VM / submit / memory / publish / userclient / service / ABI）

关键事实：`NativeAdrenoA740HwInit.h` 的头注释写明它由 `scripts/derive-a740-hwinit.py` 从 pinned mesa 源码生成，并且该生成器**已经在读 `a730_protect`**：

```
/* Generated by scripts/derive-a740-hwinit.py from the pinned a6xx.xml/adreno_common.xml/a6xx_gmu.xml (A7XX
 * variants) and a6xx_catalog.c (a740_hwcg, a730_protect). Dword register offsets. Do not edit by hand. */
```

`derive-a740-hwinit.py` 的 variant 解析器只认 `A7XX` 这一档，而 Adreno 730 正属于 A7XX（GEN7 从 a730 开始）。也就是说：**换一张 A730 的 hw_init 表是「改生成器的 variant + 换 a730_hwcg 表名」，不是重写 1.1 万行 KMD。**

这把「官方路线 = 数周」改判为「官方 KMD 移植 ≈ 750 行代际工作 + 板级文件」，与 §1 的交付层复用相加，是可执行的。

## 3. 里程碑与验收（每条都先有离线证据再上机）

- **M1 生成 A730 寄存器表**：`scripts/derive-a730-hwinit.py`（从 `derive-a740-hwinit.py` 派生）+ 单测断言表内每个符号都能在 pinned XML 里解析、`a730_protect` 计数与 `DECLARE_ADRENO_PROTECT(a730_protect, N)` 一致。产出 `NativeAdrenoA730HwInit.h`，与 A740 版本做 diff 报告（哪些寄存器偏移不同）。
- **M2 板级文件**：`NativeAdrenoBoard` / `Pwrup` / `GpuContext` 的 SM8475 版本：GPU SID、CX/MX 电源域、GMU 固件名（`a730_gmu.bin`/`a730_sqe.fw`，以设备 `/vendor/firmware` 实际文件为准）、时钟频率表。**取值必须来自设备侧证据（DT / firmware 目录 / Android 日志），不许推测。**
- **M3 离线编译**：`build-adreno-metal-plugin.py` + `make-gpu-addon.py` 走官方三步，产出 `NativeAdrenoMetal.bundle` 与 `gpuaddon.bin`；`check-adreno-*` 系列门禁全绿；`k60_metal_blob` 换成 addon 或保持双轨（先并存）。
- **M4 首帧**：官方插件 + A730 KMD 上机，判据 = `present #` ≥ 1、`crashed: backboardd` = 0、SpringBoard `turns > 0`（`turns=0` 是主线程卡在同步 Mach 调用的判据）。
- **M5 帧率与跟手**：`present #` 的 `encode/commit/wait` 分段（官方页给了参考量级：linear encode 222 µs、texture 5,099 µs、整帧 15.8–16.3 ms），再加预热与 `metal-flow=1`；目标 120 fps（8.3 ms/帧），验收 = 连续 300 帧 `present` 且 P99 帧时长 ≤ 8.3 ms。

## 4. 当前阻塞（如实记录）

- `.cache/adreno-source` 不存在：`scripts/fetch-adreno-inputs.py` 在 WSL 里报
  `urllib.error.URLError: <urlopen error [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol (_ssl.c:1000)>`
  —— 与本项目此前的 IPSW 取流同一类 WSL 出网问题（重试或改 Windows 侧取）。**没有这份源码就无法生成 A730 表**，M1 从这里开始。
- 现有 Pong 路线的观测事实（不能丢）：插件已实例化、`crashed: backboardd` 0，但 `Pong Metal: S c0/0 d0 p0 x6`（6 个 selectors 无答案）与 SpringBoard `turns=0`。官方路线不是「修这 6 个」，而是换掉 KMD+插件这一层；两条路线要分别记判据，不能混为一谈。

## 5. 不做的事

- 不把 `drivers/Adreno740` 硬搬当 A730 用（寄存器表不同，会写坏 GPU）。
- 不在未取得 `present #` 之前调 `metal-flow` / 预热（没有帧可预热）。
- 不把「插件 loaded」「provider published」当硬件加速成功的证据 —— 本仓库已出现过桩实现冒充真设备（`0212`）。
