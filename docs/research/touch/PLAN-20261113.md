5. 产物与日志在 `E:\k60-work\artifacts\<tag>\`，不污染冻结输入。

`scripts/verify-boot-image.py --manifest M --image I`：
1. 按 Android boot header 实际边界解包：kernel 槽是「一个 gzip member（112 B shim + 3,145,728 B FD）+ 其后 4,024 B 裸 DTB」，必须用 `zlib.decompressobj(16+zlib.MAX_WBITS)` 读 `unused_data`（`gzip.decompress()` 会报 `BadGzipFile`）。
2. 从 payload FAT 读回 kernel/ADT/TOML，逐项比 manifest SHA；任一缺失/截断/布局歧义/哈希不等 → fail closed。
3. 参数三处来源分开报告（见 §0 与 v3 §0.4），只拒绝 `pong_adsp=1`，允许 `pong_adsp=0` 或缺失。
4. DTB >64 KiB 拒绝（P-149）。

## 5. 基线通过后的触摸实施顺序

1. 先验证当前 probe/DT 与驱动初始化路径：为什么 `identification failed`。读 `pong_goodix.c` 当前初始化状态机与 `SE4`/FIFO 日志，确认是供电、复位、还是 SPI 通路。
2. 补真实 `Pong touch: POLL hb int=… polls=… reports=… touches=… bad=…` 计数（受控频率，例如每 64 次轮询一行；不得无限刷）。INT 上升或读次数增加不得记成 `reports`。
3. 供电方向：用官方资料/同型号证据/固件反编译确认 RPMh/regulator provider、ABI、DEPEX、资源 ID、电压与错误处理。接口成立后做最小 UEFI 电源请求 + 失败日志，再真机验证 ACK、交接保持、芯片通信。未测电压标"未测"，不猜 PPID 通道/MMIO，不把一次 ACK 当触摸成功；接口无法证实就交阻塞证据，本轮不改 ABL。
4. 在可通信/供电证据成立后重采原始 BRL 帧，只有当前读数复现偏移才改解析；保持 Mode 0、已验证 GPIO（MISO 17 / MOSI 18 / CLK 16 / CS 19 / RESET 20）、333 kHz。
5. 每次修改重建冻结清单，走 strict 构建/校验/归一启动流程。
6. 不修改 `0340/0391/0401` blob，不编辑 `board.toml kernel_args`，不重排 `series`。
