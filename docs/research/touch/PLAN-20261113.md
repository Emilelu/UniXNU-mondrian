## 2. 严格构建与参数审计（Lead 基线基础设施，触摸任务只消费）

`scripts/build-strict.sh <tag> --fd <FD> [--kernel-arg …]` 必须满足：

1. 透传真实退出码（不得用 `grep`/管道掩盖；P-181 的教训）；本轮先 `touch` marker，构建后要求 `kernel.macho -nt marker` 且非空。
2. 清除继承的 `UNIXNU_SKIP_GATES`，不提供 skip 开关；完整跑 `static_check` / `unit_test` / `artifact_check`。
3. 显式 `--fd`，归档到 `E:\k60-work\artifacts\fd\<tag>-<sha12>.fd`，manifest 记录来源提交与完整 SHA-256。
4. 写版本化 `build-manifest.json`：三仓提交/子模块/工作树状态、`patches/xnu/series` 顺序指纹、构建命令、时间、门禁结果、日志路径、以及 kernel（原始与 payload 内）、payload、boot image、FD、ADT、DTB 的完整 64 位 SHA-256。**区分**原始 kernel 与 payload 阶段被修补后的 kernel，不做错误比较。
5. 结构化解析 `board.toml [kernel_args]` 与最终 payload `unixnu.toml` 的 entry/confirm 参数，按名称+值做有序比较并报告差集；重复/冲突值显式列出；未解释的注入直接失败。
6. 产物与日志写入独立目录（`E:\k60-work\artifacts\<tag>\`），不得污染冻结输入。

`scripts/verify-boot-image.py --manifest build-manifest.json --image boot.img` 必须：

1. 按实际 Android boot header 版本/长度边界解包（不硬编码 shim 长度），定位 shim/FD、尾部 DTB、ramdisk FAT。
2. 从 payload FAT 取出 kernel/ADT/`EFI/UniXNU/unixnu.toml`，逐项与 manifest 的本轮产物比 SHA；任一缺失/损坏/截断/布局歧义/哈希不等 → fail closed（拒绝上机）。
3. 三处参数来源分开报告（见 §0.4），只拒绝 `pong_adsp=1`。
4. ADT 只做文件身份校验，不解析"ADT 参数区"。

## 5. 基线通过后的触摸实施顺序

1. 先验证当前 probe/DT 与驱动初始化路径，补真实 `Pong touch: POLL hb … polls/reports/touches/bad` 计数；INT 变化或读次数增加不得记成 `reports`。
2. 供电优先：用本地官方资料、同型号证据、固件反编译确认 RPMh/regulator provider、ABI、DEPEX、资源 ID、电压请求与错误处理（静态接口准入，不要求实时 ACK 才写代码）。接口成立后做最小 UEFI 电源请求 + 失败日志，再真机验证 ACK、交接保持、芯片通信。未测电压标"未测"，不猜 PPID 通道/MMIO，不把一次 ACK 当触摸成功；接口无法证实则交阻塞证据，本轮不改 ABL。
3. 在当前可通信/供电证据成立的基线上重采原始 BRL 帧，复现 `0x10308/0x10309` 偏移后才改解析或 ACK 地址；保持 Mode 0、已验证 GPIO 与 333 kHz 频率，不把电源/协议/时序猜测混成一次实验。
4. 每次修改重建冻结清单，走严格构建/校验/归一启动流程。
5. 不修改 `0340/0391/0401` blob，不编辑 `board.toml kernel_args`，不重排 `series`；需要触及则停下交 Lead。固件改动走独立功能分支，不污染已验证 main。
